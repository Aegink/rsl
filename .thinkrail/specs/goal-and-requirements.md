## 目标

给「阅读源」一个**可编译、可测试、跨端一致**的描述语言，以及一个不依赖 JVM 的内核实现。
一句话判据：**同一份源文件，在 iOS / Android / WASM / CLI 上得到同一个结果；任何失败都有错误码，永不静默返回空串。**

RSL 不追求与 Legado 兼容。它要解决的是 Legado 无法通过打补丁解决的三件事：规则是字符串没人检查、脚本逃生舱把宿主绑死在 JVM、阶段之间靠全局 map 隐式通信。

## 范围

**在内**：

- 语言与契约：选择器命名空间、管道、表达式、五阶段输出契约、错误模型、预算、测试格式。
- 内核：编译（解析 → Schema → 语义分析 → IR）与执行（请求、解析、调度、缓存、脚本沙箱）。
- 载体：novel / comic / audio / video / file / rss 六类，且**载体可逐条覆盖**（聚合源一本书一个载体）。
- 真实站点必需的能力：多步签名、登录态、编码、字体反爬、WebView 取数、媒体解密、第二轨道（弹幕/歌词）、分页游标。
- 工具链：`rsl compile / run / record / test / lint / build / pack`。

**在外（宿主职责，标准只定义契约）**：

- 聚合检索的合并、排序与去重（宿主调 `searchMany`，引擎只保证单源正确）。
- 书架、历史、推荐、购买、评论页的 UI。标准给数据契约（`hostStages`），不给控件。
- 内容分发：仓库不含任何书源、站点信息或公共实例。

## 非目标

- **不做 Legado 兼容层。** 存量源通过一次性转换器（`rsl convert`）迁移，转换器是工具不是内核依赖。
- **不做任意自定义 UI。** 发现页筛选器是「数据选择声明」（`filters`），不是控件编程。
- **不把聚合塞进单源。** 一个源 = 一个站点；`data:` 伪协议式的上下文编码被明确禁止。

## 验收

1. 从零按规范写一个「带登录 + 多页目录 + GBK + 字体反爬」的源，不需要读内核源码。
2. 该源能在 CLI 下编译、运行、录制、回归测试。
3. 20 个故意写错的负例全部得到明确错误码与修复提示。
4. 逐章规则里出现网络或脚本调用时，**编译期**即报 `E_COST`，而不是运行到 19 秒才发现。

> 以上验收由用户口头确认过目标方向（2026 年这轮重构），具体阈值尚未逐条复核，标为未确认。
