### 0.3 完成定义（DoD）

一个任务只有达到对应等级才算完成，**低等级通过不得写成高等级可用**（`S§13.2`）。

| 等级 | 含义 | 证据 |
|---|---|---|
| **L0 静态** | 代码写完、能编译 | `cargo check` 通过 |
| **L1 编译** | 加载期语义检查生效 | 负例报出**正确错误码 + 正确 path** |
| **L2 模拟** | 用 fixture 跑通，不联网 | `rsl test --level L2` 全绿 |
| **L3 真实 HTTP** | 对真实站点跑通 | 记录响应、可复现 |
| **L4 WebView** | 需宿主渲染的路径 | 真机/模拟器截图 + trace |
| **L5 三端一致** | CLI / WASM / iOS 同一 fixture 逐字节一致 | 哈希相等 |

**M1 的验收上限是 L1；M3 是 L3；M6 才是 L5。**

## 2. 多维交叉验证

### 2.1 九个维度

| 维 | 名称 | 判什么 | 缺失意味着 |
|---|---|---|---|
| **D1** | 规范条款 | 有没有被正文定义 | 该能力没有合法写法 |
| **D2** | Schema | 编辑器能不能提示、CI 能不能拦形状 | 只能靠编译器兜 |
| **D3** | 示例 | 有没有可运行的合法样例 | 作者不知道怎么写 |
| **D4** | 编译期检查 | 错误能不能在加载时被抓住 | 只能运行时炸 |
| **D5** | 错误码 | 失败有没有名字与处置 | 用户看到空串 |
| **D6** | 内核依据 | 为什么需要它（Legado 事实） | 可能是臆想需求 |
| **D7** | 配方 | 作者会不会用 | 规范对、但没人写得出来 |
| **D8** | 迁移 | 存量源能不能过来 | 生态断代 |
| **D9** | 测试 | 有没有回归保护 | 改一次错一次 |

**一行的九列全绿 = 这条能力可交付。任一列空 = 交付前必须补或明确豁免。**
